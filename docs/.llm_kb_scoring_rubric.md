# LLM_KNOWLEDGE_BASE.md Scoring Rubric (Harness Constraint)

## Purpose
This rubric constrains the Agent Team (Architect → Writer → Evaluator) for optimizing the LLM Knowledge Base. The document PASSES when total score >= 90/100.

## Target Consumer
LLM agents (Claude, GPT, Copilot, Cursor, etc.) that need to:
- Generate correct Odoo 18 code for this module
- Answer technical questions about this module accurately
- Debug issues related to this module
- Extend or modify this module

## Scoring Dimensions (100 points total)

### 1. Structural Parseability (20 points)
| Criteria | Max | Scoring |
|----------|-----|---------|
| YAML front-matter is complete (all model names, routes, groups, dependencies, file paths) | 5 | -1 per missing key field |
| Every section is independently parseable (no forward references required) | 5 | -1 per section that requires reading another section first |
| Heading hierarchy is consistent (H2 → H3 → H4, no skips) | 3 | -1 per heading level skip |
| Tables use consistent column naming across sections | 3 | -1 per inconsistency |
| Sections have machine-readable anchors/IDs usable for retrieval | 4 | -1 per major section missing clear anchor pattern |

### 2. Technical Accuracy (25 points)
| Criteria | Max | Scoring |
|----------|-----|---------|
| All XML IDs match actual source code exactly | 7 | -2 per incorrect XML ID |
| All field names, types, comodel_name, required, default values match source code | 7 | -2 per incorrect field spec |
| Security matrix (ACL + record rules) matches ir.model.access.csv and rules.xml exactly | 5 | -2 per incorrect permission |
| Code snippets are syntactically correct and match source | 3 | -1 per incorrect snippet |
| Domain expressions, route paths, controller signatures match source | 3 | -1 per mismatch |

### 3. Token Efficiency (15 points)
| Criteria | Max | Scoring |
|----------|-----|---------|
| No duplicate information across sections (e.g., field list appears once, referenced elsewhere) | 5 | -1 per significant duplication |
| Tables preferred over prose for structured data | 4 | -1 per block that should be a table |
| No filler text, marketing language, or unnecessary adjectives | 3 | -1 per instance |
| Code blocks are minimal (show pattern, not full file dumps) | 3 | -1 per unnecessarily long code block |

### 4. LLM Task Orientation (20 points)
| Criteria | Max | Scoring |
|----------|-----|---------|
| Has decision trees for common tasks ("How to add field", "How to add portal route", "How to change permissions") | 6 | -2 per missing common task |
| Each task guide includes: preconditions, steps, affected files, side effects | 5 | -1 per incomplete task guide |
| Includes "gotchas" and anti-patterns specific to this module | 4 | -1 per missing known pitfall |
| Provides copy-pasteable code templates for extension tasks | 5 | -1 per task missing template |

### 5. Self-Verification Capability (10 points)
| Criteria | Max | Scoring |
|----------|-----|---------|
| Has truth tables for computed fields (input → output) | 3 | -1 per computed field missing truth table |
| Has assertion-style checks (e.g., "If user is Portal, they MUST NOT see woow.service.category") | 4 | -1 per missing security assertion |
| Includes edge case catalog with expected behavior | 3 | -1 per undocumented edge case |

### 6. Completeness (10 points)
| Criteria | Max | Scoring |
|----------|-----|---------|
| Covers all models, fields, methods, views, actions, menus, security groups, record rules, portal routes, templates, CSS classes, demo data, i18n, deployment, testing | 8 | -1 per missing topic |
| Has a quick-reference cheat sheet for XML IDs, table names, imports | 2 | 0 or 2 |

## Harness Rules for Agent Team

### Architect Agent Constraints
- MUST read actual source code files before analyzing the knowledge base
- MUST produce a structured blueprint with section-by-section recommendations
- MUST identify all technical inaccuracies by cross-referencing source code
- MUST NOT suggest changes that add marketing language or filler

### Writer Agent Constraints
- MUST follow the Architect's blueprint
- MUST cross-reference every XML ID, field name, and domain against source code
- MUST keep total document under 1200 lines (token budget)
- MUST NOT introduce information not present in source code
- MUST use tables over prose wherever possible

### Evaluator Agent Constraints
- MUST score strictly against this rubric
- MUST cite specific line numbers or sections for every deduction
- MUST verify at least 5 random XML IDs against source code
- MUST verify at least 3 code snippets for syntactic correctness
- MUST NOT pass a document with any technical inaccuracy in security or permissions
```
